# 超级泡泡实时岗位状态看板

生产试运行： https://z58479874.github.io/super-bubble-status-board/

## 014.1 员工管理

店长登录 → 人员 → 员工管理。支持在职/历史人员筛选、姓名/编号搜索、新增全职或固定兼职、编辑资料、可安排岗位、离职与恢复、PIN初始化/重置。与今日是否排班和营业阶段无关。

只有店长可操作长期人员档案，最终权限由已部署的受控RPC校验。新增不自动排班、不自动授予岗位、不生成PIN。恢复使用原编号和历史岗位关系，需重新初始化PIN。

正式代码位于 site；GitHub Actions 校验后发布。所有资源使用相对路径。config.js 只包含浏览器公开配置；不提交服务端密钥、真实PIN或会话凭证。

当前读取继续使用014的前台轮询；本版本未改数据库、未加入Realtime。

## 014.2 今日轮餐

店长、副店、主管：人员 → 今日轮餐。可提前排45分钟午餐、指定接岗人、预览人数及冲突、确认风险后保存、填写原因取消。开园前显示“待营业后复核”；营业中红橙提示是计划预判，真实安全告警仍优先。

员工：我的 → 今日午餐 / 今日接岗任务。饭点只提醒，不自动开始吃饭或出发。安全岗午餐仍复用正式交接流程。

计划保存必须先预览，使用接口提供的 revision 和 preview_revision；冲突时重新读取，不自动覆盖。取消计划保留历史。普通员工不能读取全店计划，014.1员工管理仍仅店长可用。

014.2.1：总览、人员、岗位和交接继续每5秒读取；今日轮餐列表每15秒读取。安排、修改、取消及风险确认弹窗打开时，后台读取不重绘表单。若计划或现场上下文变化，只显示复核提示；原输入与旧revision保留，保存仍由数据库并发检查决定。关闭弹窗或写入成功后立即恢复并主动刷新。

### 本地开发和发布

Node 22+；`npm ci`，`npx playwright install chromium`，然后 `npm run verify:release`。
`npm run dev` 保留本地开发入口（默认 http://127.0.0.1:8782/super-bubble-status-board/）。本地完整界面模拟可用 `node tools/serve.mjs --mock`，不会连接生产数据库。

生产构建复制审核后的静态资源到 dist，保持所有资源为相对路径。GitHub Actions 运行语法、静态检查、模拟业务/UI测试与生产构建，再发布 dist。测试用虚拟身份只存在 tests，不进入站点产物；不会使用真人PIN或写生产数据。

测试继承013.2响应兼容、013.3人员操作、013.4安全返岗、014调度和014.1员工生命周期的断言；只调整测试启动方式、子路径及新增只读调用白名单。没有删减旧业务断言。使用的014.1参数契约保存在 tests/0141-contract.json。
